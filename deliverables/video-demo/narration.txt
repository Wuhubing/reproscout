Hello, I’m Weibing Wang. This is ReproScout, a scientific reproduction review tool I developed for MIT one point one two five. When a research program finishes, I still need to ask: did it run the original computation, and does its output actually support the answer?

ReproScout connects those questions in one workflow. The input is a prepared project containing original code, data or documented data sources, research questions, and a pinned software environment. The output is a retained execution record, answers linked to evidence, and a portable report that another researcher can inspect.

Here, I’m using an unchanged diabetes regression example from scikit-learn. After signing in, I upload its prepared project bundle. The app checks the archive and the input file hashes before registering it. The server needs an approved runtime. Importing a repository does not automatically resolve its dependencies.

Next, I choose the questions and set the execution limits. The controller runs the author’s code in an isolated Docker environment with networking disabled inside the scientific container. The interface keeps the run visible while it works, including partial results or failures when a task cannot finish.

The recorded browser acceptance run finished in about twenty seconds, using five model calls and an estimated model cost of less than one cent. It produced a regression coefficient, a test mean squared error, and an R-squared value. Those numbers are candidate answers. Completing execution does not, by itself, establish scientific correctness.

This is a central interaction. For the mean squared error question, I open the cited execution output. The highlighted line explicitly reports mean squared error: two thousand five hundred forty-eight point zero seven. I can check the metric name, the value, and the context, rather than trusting a generated sentence. The source integrity view shows whether any of the listed original input files were modified.

A review records a decision, an explanation, and the evidence used to support it. Reviews also preserve the reviewer’s identity and whether the reviewer is a human or an assistant. In this recorded walkthrough, the three saved decisions are assistant reviews, not independent human validation. Earlier review versions remain available.

Finally, I export the report and open it outside the application. The package preserves the answers, evidence, and review records together. Following a citation takes me to the relevant output lines. A collaborator can examine how a conclusion was reached, instead of receiving only a final number or a screenshot.

I have also tested this fixed example successfully with GitHub Actions, using the actual Docker environment and reproduction controller. That is an integration test, not a replacement for an online execution service. The public website currently presents retained evidence. The authenticated app has been verified on the development host.

My goal is to make scientific reproduction easier to examine. Preserve the original computation, expose the evidence, and record the reviewer’s judgment. The next milestone is deploying the authenticated workflow on a suitable host and evaluating it with independent researchers. Thank you for watching.
